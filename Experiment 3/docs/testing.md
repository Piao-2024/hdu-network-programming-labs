## 1. 分层、工具与可复现性

实际只使用标准库 unittest、unittest.mock、socket、subprocess、time 等。测试文件现有 tests/test_game_logic.py、test_protocol.py、test_server.py、test_client.py、test_integration.py、test_launch.py、test_uv_entrypoints.py。端到端使用两个进程和管道输入输出，无第三方终端自动化包。

| 层次 | 范围 | 隔离方式 | 通过依据 |
|---|---|---|---|
| 单元 | 命令解析、纯判型、纯结算、编码解码、客户端绘图 | 显式输入、固定抽样序列、模拟 socket | 每条断言与确定预期一致，无真实网络 |
| 集成 | 读取器与字节流、服务端调度与逻辑、客户端消息状态 | 使用 socketpair 或回环 TCP，时钟可控 | 多模块实际组合，不以纯 mock 代替完整链路 |
| 端到端 | 两个真实进程、CLI 输入输出、生命周期 | 本机终端或标准库 subprocess | 玩家可完成多盘和退出，异常退出码和呈现正确 |

固定测试来源以显式序列逐次返回值，不依赖 `random.seed` 对 SystemRandom 生效；SystemRandom 不通过种子回放。纯 classify_roll/settle_bet 不调用随机数。固定抽样序列 (6,1,6,1,5,2) 分别对应首盘预叫、首盘实际、下盘预叫；非法下注时抽样调用数不增加。生产不得添加让玩家指定实际骰子的协议字段，确定性输入仅在测试调用边界替换抽样函数。

使用单调时钟替身验证截止时间，不靠长时间 sleep。集成测试使用临时空闲端口（绑定回环端口 0 并读取实际端口），默认 5000 只用于另行检查默认参数；不要先探测再释放端口造成竞争。每次清理 socket、子进程及临时资源，测试不更改 `.venv` 或全局配置。

穷举 36 个预叫 × 36 个实际结果共 1296 组：用独立条件表作为预期来源核对 matched_types、首项优先级和 tc 特例；对每组再检查六种押注结算。预期不能通过再次调用被测 classify_roll 来生成。核对所有 net_change=payout−amount、中奖资格唯一例外、骰子顺序及重复次数。概率统计测试不是确定性判型验收的替代。

### 命令数据集

- 合法：`ya tc 10 coin`、`  ya dc 0002 silver  `、token 间制表符、`ya sx 1000000 gold`。规范化数量分别为 10、2、1,000,000。
- INVALID_COMMAND：空字符串（直接测服务端接口）、`ya tc 1`、额外 token、`YA tc 1 coin`、超过 256 UTF-8 字节、包含 CR/LF。CLI 空行本地跳过另测。
- INVALID_PLAY：`ya xx 1 coin`、`ya TC 1 coin`。
- INVALID_AMOUNT：`0`、`-1`、`+1`、`1.0`、`1e3`、全角 `１`、`1000001`、超过 10 位数字。
- INVALID_CURRENCY：`ya tc 1 usd`、`ya tc 1 Coin`。
- 组合错误按规则规定的检查次序返回第一项错误。若批准账本，再追加同币余额刚好足够、不足、不同币余额不可挪用和失败不扣款用例；当前不伪造余额不足测试成功。

## 3. 协议单元与流测试

| ID | 测试数据/操作 | 预期 |
|---|---|---|
| P01 | 协议每种消息完整示例编解码；中文及 JSON 字符串内转义换行 | 等值往返，恰好一个末尾 LF，内部没有裸 LF，消息字段符合唯一规范 |
| P02 | 对一条含中文的帧，在每一个字节偏移拆为两段；再逐字节投递 | 一条消息恰好产出一次，不在半个 UTF-8 字符处解码失败 |
| P03 | welcome+round_open 一次交付；result+open 一次交付 | 按顺序读出两条，第二次 read_message 使用已缓冲帧，不额外等待 recv |
| P04 | 一条完整帧+下一条半帧，再给剩余；多个合法帧总长超过8192 | 完整帧先返回，残留准确保留，不误触发单帧超长 |
| P05 | 合法对象补空白使负载8191字节+LF；负载8192字节+LF；无LF残片8192字节 | 第一条通过；后两条 FRAME_TOO_LARGE，关闭连接 |
| P06 | 非法UTF-8、BOM、裸换行拆坏JSON、CRLF、空行、畸形JSON | 分别 INVALID_ENCODING 或 INVALID_JSON；致命关闭，不尝试跨帧修复 |
| P07 | 重复键、NaN/Infinity、JSON数组、未知字段、bool ID、1.0 ID | 前三类为 INVALID_JSON（含非对象顶层）；后三类为 INVALID_MESSAGE |
| P08 | version=2，未知type，C→S发送round_result | 分别 UNSUPPORTED_VERSION、INVALID_MESSAGE、UNEXPECTED_MESSAGE |
| P09 | EOF无残留、EOF有半帧、recv/send异常 | 区分正常流结束与截断，均释放资源；不产生虚假完整消息 |
| P10 | 第一字节后9.9秒与10秒；持续送单字节但总时长超10秒 | 前者完整则成功，超时则TIMEOUT；追加不能延长截止时间 |
| P11 | OPEN无输入超过10秒 | 不踢出；半帧期限只在首字节到达后开始 |
| P12 | request_id缺失、0、超过上限、倒退；round_id过期 | 信封错误致命；有效类型的倒退ID为DUPLICATE_REQUEST；过期盘号ROUND_MISMATCH |

P05 在传输层验证帧边界，采用 welcome 的合法 message 加 JSON 尾随空格补齐字节，避免超过 message 字段长度。P02–P04 先模拟分段来源做单元测试，后用真实 socketpair 或 TCP 做集成复核；仅把多次 send 当作多次 recv 不成立，测试需控制读取分段或验证任意分段均正确。

## 4. 服务端、客户端集成

| ID | 操作 | 应断言的行为 |
|---|---|---|
| I01 | 新连接，使用固定抽样序列 | welcome→round_open(1)，预叫(6,1)；无客户端握手要求 |
| I02 | bet(1,1,ya tc 10 coin) | result关联1/1，实际(6,1)，金额同G01；随后open(2)预叫(5,2) |
| I03 | 同盘先非法数量再合法新ID | 非法只有error；盘号/预叫/抽样次数不变；新ID合法才结算 |
| I04 | 重复已成功ID；同盘两注以粘连帧送入 | 重复ID不重算；不同新ID但旧盘号为ROUND_MISMATCH；无额外实际掷骰 |
| I05 | 业务失败后复用ID | DUPLICATE_REQUEST；业务失败已消耗该ID，须用新ID重试 |
| I06 | OPEN发送quit | bye关联请求；EOF；服务端可接受新连接且新盘从1开始 |
| I07 | 在bet半帧/完整bet后/结果与新开盘之间强制断开 | 无进程崩溃或资源泄漏；不跨连接重放；客户端不自动重发，未收到结果时提示未知 |
| I08 | 致命编码错误后再次连接 | 旧连接关闭，新会话正常欢迎，不沿用残片与编号 |
| I09 | 客户端收到结果ID错误、未知ruleset、错误消息次序 | 显示协议错误并退出，不自行修正或重新计算结算 |
| I10 | 连续100盘，混合六玩法/币种/无效输入 | 每笔合法注恰好结算一次，ID递增、盘号仅成功后递增，错误不漂移，记录延迟 |
| I11 | 客户端渲染1～6每个面及有序骰子对 | ASCII点数与actual_dice相符；胜负和金额直接展示权威字段，不覆盖服务端值 |
| I12 | 第二个连接到达，当前会话随后退出 | 不宣称并行处理；第二连接等待/超时符合单活动会话边界；无状态混用 |

I09补充：在初次欢迎前、等待bet响应、收到结果但尚未收到新开盘时分别注入结构合法、request_id=null 的 fatal error，均应显示服务端诊断并终止；非致命error的null/错误请求编号仍视为协议错误。退出响应只允许bye或致命error，不能把非致命error当成退出成功。
